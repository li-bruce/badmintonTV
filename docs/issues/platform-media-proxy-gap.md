# 原片直出与兼容代理缺口

记录：2026-09-29；来源代码 `05329a5`。状态：confirmed_by_code；修复及新增兼容性验证 NOT_RUN。关联 S1-01、S1-02 和后续候选 R-02。

## 发现与影响

`apps/platform/main.py` 的 `/api/v1/assets/{asset_id}/media` 总是原文件 FileResponse，固定 `media_type='video/mp4'`。可探测/入库的容器和编码不一定受浏览器支持；现有约50MB FFV1/MKV派生素材用于探测回归，成功入库不等于网页能播放。单独修改MIME也不能解决浏览器缺少解码器的问题。

`frame-map` 索引大于32MB时提示生成小段代理，但目前没有自动代理生产通路。`app.js` 使用 currentTime 标记，缺少代理选择、逐帧、缩略图时间线等操作。

本轮是代码核查，没有重新播放MKV或做性能实测，不报告虚构的失败率。原H.264小样的Range及播放PASS保持原范围，不扩大到任意格式、VFR或整场长片。

## 建议修复与关闭条件

1. 根据容器/编码确定响应类型及浏览器兼容性；不可播时生成受容量约束、可缓存复用的H.264/AAC MP4代理，明确未就绪或不可用状态。
2. 原片只读，代理记录版本/哈希/源引用及显示帧→源PTS/毫秒映射；CFR重帧/丢帧不能按固定fps反推源真值。
3. 有界/分段提供长片frame-map，提供小段代理任务；重复打开不重复复制原片，代理和临时峰值计入platform60GB。
4. 真实CFR、VFR、FFV1/MKV、长片分别测试播放、固定30点寻帧、标注保存/重启/回写、取消与失败。目标往返误差≤一个源帧，并报告实际误差及中位数/P95延迟。
