## 本轮先行断言

- 输入：本地标准库构造的单卷 ZIP/ZIP64 夹具；没有网络下载或额外大文件写入。
- 预期：在 `ZipFile` 分配目录前核对经典 EOCD、ZIP64 locator、ZIP64 EOCD 的绝对偏移、长度、条目数、目录长度及单卷字段；经典字段非哨兵值时必须与 ZIP64 值一致。
- 预期：目录最多 10,000 项/16 MiB；单成员只允许 STORED/DEFLATED；已有 CRC、hash、路径链接、重复成员、配额和防覆盖边界保持通过。
- 预期：伪 locator、截断/冲突 EOCD、多个卷、过大目录/条目及含歧义签名的尾记录必须在 `ZipFile` 前拒绝。ZIP64 中央目录字段需按序解析，不能由 ZIP64 扩展覆盖已经检查过的边界。
- 验证命令：`python -m unittest discover -s tests/library -p test_archive.py -v`。
- 开发前状态：NOT_RUN；工程子断言的最终结果见下节，真实 `R-04a` 状态由主任务维护。

## 范围和性能取舍

采用 Python 3.12 `zipfile`，其 ZIP64 读取只支持固定 56 字节 EOCD（size=44），不支持 ZIP64 extensible data sector。本模块显式拒绝该扩展、多卷、需要 stdlib 修正偏移的拼接归档、尾附内容等不在本轮范围的变体，避免自身预检与 stdlib 最终加载不同的目录。成员 ZIP64 extra 必须唯一、字段数量和顺序对应经典字段中的哨兵；冗余或冲突 extra 不猜测解释。

API 保持 `inspect_zip` / `extract_member` 不变。保留每次提取前后完整计算源 SHA-256；不使用仅由 mtime/大小判定的缓存，也不增加可绕过 hash 的参数。10 个文件对 6.5GB 归档约产生 130GB 顺序读取，这是 I/O 成本而非额外磁盘容量。若以后提供批次原子发布，可在同一只读句柄内对整批前后核验两次，再发布全部产物；本轮最小实现暂不引入该新接口。
