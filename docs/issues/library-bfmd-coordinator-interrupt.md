# BFMD 并发协调器的中断边界

2026-09-29为低速公开连接增加单owner、最多两份不同文件的并发能力。实际121文件在实现期间恢复高速，最终全部由原顺序writer自然完成，没有结束其进程或重启。因此真实双流/停止/Range恢复均NOT_RUN。

独立审阅在实现中确认并修复三个窗口：

1. submit已启动任务、future尚未登记时Ctrl-C：独立完成队列保存结果，owner离开线程池后仍在同一锁和配额内回收，完成项不丢失。
2. owner检查继续标记与任务真正开始之间另一任务失败/新停止标记：worker在入口再次检查，尚未获得许可的任务不进入文件或网络操作，也不计为已尝试。
3. Python3.12重复Ctrl-C中断Thread.join可令其状态提前看似停止：Condition保护独立active任务计数，完成结果先入队才减数；owner等待active=0后再join清理资源。不能把线程对象状态当文件写者完成证明。

确定性临时文件/真实线程回归覆盖上述窗口；真实join acquire边界注入中断的测试对旧控制实现确实失败，对新实现通过。没有因此放宽下载校验、删除锁或失去文件级字节限制。失败或停止后旧verified清单保持，主线程统一发布已在途成功，然后返回原失败/停止结果。
