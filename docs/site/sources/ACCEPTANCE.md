# 案例与验收

以下数量和门槛是本项目待验证的工程目标，绝非已有模型成绩。若数据不够，报告不足，不虚构样本。

各阶段当前的目标断言、达标/未达标、证据及下一步统一维护在 [分阶段验收表](STAGE_ACCEPTANCE.md)。本文件保留验收标准；已实现/实验中等研发状态不替代 PASS / FAIL / BLOCKED / NOT_RUN 结果，只有阶段全部必需项 PASS 才能宣布阶段达标。

## 案例顺序

1. 无模型人工闭环：选2–3段真实网前片段 → 标注源时间/球员/区间 → 文字或结构化条件查询 → 人工确认 → 拼成1080×1920短视频。没有证据的手法只标“网前击球/待确认”。
2. 展搓/收搓验证：写可观察定义，保留正反手、拍面/手腕可见性、触球前后窗口与球路证据。先少量双人复核/专家确认样本，有歧义则保留unknown。比较细标签与仅粗网前标签；不能用粗球种迁移标签充数。
3. 后退小跳启动：准备→离地/重心变化→落地启动→后退区间，脚部可见；与原地垫步、普通后退步、起跳击球区分。骨骼时序优先验证，保留拍摄方向。
4. 多拍/手脚组合：同球员同回合的事件关系查询，可在其击球间插入对手事件；避免把“随后”等同于数据库相邻一行。

## 数据与评测

- 初期选约20–30条中文查询，覆盖单拍、步法、组合和先后顺序；机器可验证的纯合同示例与真实标注分开。
- 原始比赛/录制会话为划分单位。同场回放、转码、相邻片段、同源重传不能跨train/validation/test。
- 先少量小样验证可观察性，再扩大。个人录像未提供时可以先做广播素材，但必须把个人录像效果标记未测，不能用合成视频补成绩。
- A=现成文字视频召回；B=骨骼/位置/时序标签；C=融合。相同数据、查询与审片预算比较。规则+人工事件索引是产品上限参照。
- 报告每类的数量、可见性覆盖率、P@K（K=min(20,候选数)并注明）、召回（只有完整真值才能算）、时间边界误差、错人率、混淆、每小时视频处理耗时、显存峰值和人工审核量。
- 个人/转播、单打/双打、机位/场馆分别报告；不可只报总体平均。
- 研究阶段可先提出 P@20≥0.80、完整真值上的候选召回≥0.80 作为候选门槛，但必须附样本量与不确定性；小于每类30个可判定测试正例或只有一场比赛时不得宣称泛化通过。正式支持范围须依据实测另写决策，不受该数字强迫训练。
- 没有细标签真值就先做环境、基线推理、数据准备、预标注工具；不能用伪标签在同份数据上训练测试并宣布达到底座要求。

## 业务底座验收

可配置库与导入真实视频；网页定位与标注保存；重启后恢复；工具导入/导出回写正确；LLM配置密钥遮盖；未安装模型明确不可用；分析/检索/渲染任务有真实状态与错误；取消与进程中断得到正确记录；人工标注可检索；选片可保存时间线并调用渲染器。至少一次浏览器验证完整操作路径及一次服务重启验证。

## 竖屏成片验收

2–3个真实源片段完整合成；默认contain保留球员、羽球、场地，不强制中心裁掉信息。可调顺序、边界、标题、慢放；无音轨与有音轨都能处理。视频尺寸1080×1920、编码可正常播放、全程可解码、音画同步、时长与速度换算相符。保存源文件/时间码到输出时间映射。模型生成的比赛动作不能混入真实集锦。

## 完成状态

- implemented：代码存在但不代表验证通过。
- verified：明确命令与数据下验证成功。
- experimental：有结果但不足以承诺支持。
- blocked：有具体外部/数据/兼容问题，独立MD说明与下一步。
- unavailable：组件尚未安装/训练完成；产品应能容纳此状态。

项目整体验收最终须跑一次真实“导入→标注→检索→人工确认→竖屏导出”，不能以四个模块各自的通过替代。
