# 第二轮实施：技战术数据集工作台与可读框架手册

日期：2026-10-02。基线：main `207c937`。依据用户最新授权、[完整能力方案](END_TO_END_CAPABILITY_PLAN.md)及触球mark讨论。本文先登记目标与断言，再实施；工程验收与专家标签/模型精度分开。

## 1. 本轮交付与实施顺序

用户现在需要能实际使用的浏览器工具来构建训练数据。先完成“选择训练视频 → 标回合/触球/动作 → 记录手法、步法及双方态势 → 修订 → 分组划分 → 导出不可变快照 → 模型侧检查”的完整链。同时保留制作素材的检索、成片功能。

三个旧动作是回归案例，不限制目录。使用分层、多标签目录，覆盖击球、步法、球路、本人/对手/搭档状态及多拍模式。未知、不适用、未标、看不清分别保留；机器或agent标注不能冒充专家人工真值。

优先复用现有FastAPI、原生浏览器播放器、源PTS、持久任务和已有Label Studio适配。比较VIA、CVAT、Label Studio及体育开源项目后，选择能降低操作成本的交互/组件；不为了套模板再部署第二套不相通的业务库。

阶段A：共用训练标注合同、词表和真实视频清单。阶段B：可用工作台、保存与导出、模型侧审计、mark裁剪规则。阶段C：真实视频浏览器闭环、重启、用途隔离、MD转Web手册与集成。专家标注和训练准确率没有证据时继续BLOCKED，不妨碍交付标注工具。

## 3. 共用设计约束

### 3.1 训练工作区和制作工作区

训练工作区独立路由与数据表，参考`/training`和`/api/v1/training/*`。允许注册并预览经校验的training_only媒体，但不能调用制作Asset导入绕过用途限制。训练项目、标注和快照都保持training_only；生产Event、搜索、Timeline及render继续拒绝训练来源。general素材若用于训练，也必须通过明确的训练项目引用，不能自动反向发布训练标注。

只读引用D:/video原片，输出落在各owner配额中。不得把任意本机路径做成通用文件服务。媒体请求必须通过已注册asset身份与路径检查；注册需核验原片hash及可信目录来源，派生预览带回源映射。

### 3.2 统一时间和标注对象

公共合同由01在`packages/contracts`新增兼容模型/JSON schema，保持旧Event/Timeline兼容，使用`schema_version: 1.0`。新快照应有明确format标识，防止误认成制作EventManifest。

- Project：稳定ID、名称、用途、目录/词表版本、修订信息。
- Video引用：asset_id、原hash、相对路径、duration、真实PTS引用、来源与match/group信息。match_id未确认时不得伪称独立比赛。
- Annotation记录：record_id、project_id、asset_id、kind、source时间、player/team/rally关系、多标签、可见性/unknown原因、证据、审核来源、revision及前一版本。
- Contact mark：一个原片触球时间及可选不确定区间，不要求把它伪装成有长度的事件。可关联击球者和回合；触球遮挡可unknown。
- Interval：回合、动作/步法、战术模式等使用半开区间；起止有序且在媒体内。回合结束需要独立死球mark，不能默认最后一次触球就等于结束。
- State：可选的本人/对手/搭档位置（标明归一图像坐标或校准场地坐标）、移动/来去球、来源与缺失原因。没有校准不能把图像点击包装成真实米制场地坐标。
- Revision：保存时expected_revision；冲突409；修改不覆盖历史。界面区分保存、待审核、人工确认、拒绝；agent流程验证保持agent。
- Dataset snapshot：稳定ID、format/schema、项目/词表版本、资产引用、标注修订、分组split、质量摘要、生成时间、内容hash。不可变、可重复读取；仅明确human confirmed且语义有效的标签进入默认训练视图，其余保留在审核视图/排除原因中。

合同fixture由01发布，其余模块兼容消费；模块内部可先实现适配器，但不各造不同快照格式。标签键不再固定三个例子，保留原始标签和映射关系。

### 3.3 工作台交互

默认显示三列或宽屏工作布局：视频列表/进度；大播放器＋时间线；当前标注属性。让用户通过中文标签按钮/下拉操作，常用流程不要求手填JSON、asset_id或rally_id。

必须有播放/暂停、速度、时间定位、明确的前后帧/时间步进语义；触球mark、回合起止、动作区间；点列表返回原片；编辑/删除可追溯；快捷键帮助且输入框内不触发快捷键；未保存提示与保存错误反馈。精确帧标记要有源PTS证据，普通浏览器seek不能冒称帧精确。

词表分层筛选，允许多标签及unknown，支持关联球员/队伍；回合和人物可从列表选择。状态录入先用明确字段及图像点位，复杂轨迹交给可选标注工具。训练页面展示真实完成数量，不生成假的模型进度。

快照导出在页面可点击完成，展示按真实比赛组划分、未确认标签、unknown与未分配组等阻塞原因。提供JSON/JSONL等机器可读产物和可读摘要，不复制视频。

### 3.4 触球mark与裁剪策略

mark是时间锚点；按用途生成逻辑范围，原片不硬切：球路为本次触球到下一次触球/死球；手法为触球前后可配置上下文；步法覆盖启动、到位、击球、落地、回位；回合从发球到死球并可加审阅余量。范围限于当前回合/媒体，不跨回合，不按相邻行误认同球员。

生成范围继承源用途、mark/revision、规则版本和unknown。缺回合终点、下一触球或阶段信息时给明确缺失/保守候选，不假造精确边界。离线可以使用后续动作，实时模式必须声明未来信息和等待时间。

## 5. 环境、预算与运行约定

继续使用现有隔离环境。01测试端口18082、主线18080；其它任务不占用这两个端口，不重启主线。04只用CPU。03持有本轮GPU协调权，先检查账本和用户进程；没有数据不启动无意义训练，不自动开启长期作业。

先复用已下载数据和权重。每个owner开工记录容量与新增峰值：本轮平台标注/快照/有限预览先控制在额外2GB内；文档及源码小于50MB；模型新增特征/小窗优先控制在2GB内，较大下载必须有明确必要性与原配额预检。总700GB及现有固定owner配额不变。

不向全局Python安装库。若引入开源代码/前端库，记录来源、版本、license及用途，打包本地资源避免依赖外部CDN。Markdown网页由本地构建或受控渲染生成，不执行文档内任意脚本。
