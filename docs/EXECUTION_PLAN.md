# 四任务实施与资源分配

用户提出的四任务边界合理。微调：模型任务先基线评测再训练；资料任务同时交付来源/划分清单；底座持有统一标注和调度；集锦只消费已审核片段。当前主任务持有总架构、跨模块合同和最终Git集成，不额外拆成大量微服务。

## 并行任务

| 模块 | 首轮交付 | 依赖 | 允许先行的验证 |
|---|---|---|---|
| platform | 细化设计、Python Web/API/DB、素材/标注/工作流/模型与LLM配置/检索/时间线、持久worker | 本合同；通过适配器消费其余模块 | 无模型时人工索引→搜索→渲染 |
| library | 检索资源、下载小样、媒体/标注manifest、来源和split、容量受控下载器 | 配额规范；稍后接平台入库 | 下载/校验/ffprobe/重复去重 |
| models | WSL Conda、5090兼容实测、A视频/B骨骼/C融合基线、必要的小模型训练、独立报告 | 真实素材；细标签真值才能正式训练评估 | 环境与算子烟测、预训练推理、可复现离线适配器 |
| render | Python渲染包、时间线/源映射、竖屏构图、2–3片段完整MP4、QA | 手工确认片段，不依赖模型 | 合成烟测后真实素材成片 |

阶段：统一设计提交 → 四条线开发 → 小样/手标/无模型闭环 → 基线与针对性补标 → 需要时训练 → 跨模块真实闭环验收。模型未达标不会阻塞业务底座，但会限制“自动识别”的可用范围。

## 环境事实（2026-09-28已检查）

- Windows GPU：RTX 5090，32607 MiB，驱动591.86；WSL内nvidia-smi能看到同一张卡。
- WSL：Ubuntu，WSL2，运行中；docker-desktop也存在，但训练只使用Ubuntu。
- Ubuntu PATH有 `/usr/bin/python3`，未找到conda和ffmpeg；尚不能称训练环境已就绪。
- D:\video 初始为空；D盘约968,079,273,984 bytes可用。后续任务每次重测，不依赖初始数值。
- 普通沙箱枚举WSL遭权限限制，授权提升后的只读检查成功。不是硬件不支持。
- WSL启动曾提示localhost代理未映射；下载若受影响记录具体网络问题，不绕过安全配置。

## 存储硬约束

硬上限700,000,000,000 bytes，按十进制GB保守解释用户“700G”。第一轮分配650GB，50GB留余量且**不得自动借用**。以下预算为上限，不是下载目标；从几GB样本开始。

| 存储分区 | 独占写入负责人 | 上限GB | 内容 |
|---|---|---:|---|
| `D:\video\data` | library | 300 | 赛事、数据集、原始标注、下载临时/解压、共享素材handoff |
| `D:\video\platform` | platform | 60 | 代理、缩略图、索引、标注导出、数据库与备份、平台临时数据 |
| `D:\video\models` | models | 180 | 权重、HF/Torch缓存、特征、训练checkpoint、实验输出 |
| `D:\video\render` | render | 40 | 渲染缓存、中间片段、最终MP4、QA与handoff |
| `D:\video\runtime` | models建立公共Conda；各任务写自己的env/cache子目录 | 70 | Conda安装/包缓存、环境、工具；按下述二级额度 |
| 未分配安全余量 | 主任务调配 | 50 | 不可自行占用 |

runtime二级额度：公共Conda及包缓存15GB，models环境35GB，platform环境10GB，library环境5GB，render环境5GB。最好把环境放D盘；若Linux原生文件系统是兼容/性能要求，记录绝对路径并同样计入对应额度（不能靠换路径绕过预算）。数据库原生路径算platform额度。所有项目新增长期缓存均纳入统计。

并发安全：固定、不重叠的owner预算保证各任务不能分别使用700GB。每个owner内部所有并发写入必须使用同一个原子预留账本/单下载器，预留“下载+解压+衍生物”峰值；未知大小预留有限最大值，超出即中止。运行前测总已用+活动预留+本次峰值，满足owner额度且小于总硬上限，并留足物理磁盘空间。已有文件只统计，不自动删除。

共享记录：各任务把可消费结果写到自身 `handoff/`，先临时文件后原子改名。其他任务只读。小型manifest/实验说明可以进Git，大数据不能进Git。

## 环境与GPU协调

models任务是唯一公共Conda安装者，优先官方Miniforge并校验来源；只在必要时选择其他发行版。建立隔离的 btv-models / btv-pose / btv-video 环境，按实际兼容需要拆分，不要求一次全部安装。其他任务可先用自己的`.venv`进行轻量开发，之后共享Conda可用时使用本任务独立环境。记录Python、依赖锁、WSL、驱动、torch/CUDA、FFmpeg构建信息。

不修改Windows驱动，不在WSL安装Linux显卡驱动，不向base/system Python散装依赖。模型权重下载到models，公共包缓存到runtime，环境变量HF_HOME/TORCH_HOME/TMPDIR/PIP_CACHE_DIR等显式设置。

初始GPU实验优先给models；render先验证libx264 CPU，平台模型启动暂标unavailable。平台实现GPU租约后，分析/训练/本地LLM/需要GPU的编码通过同一调度入口序列化。网络、编译、算子、显存、数据不足、准确率不足分别记问题，不能统称“算力不够”。

## Git与交付

创建main初始设计提交后，四任务从该提交创建worktree。任务名与ID写docs/STATUS.md。各任务在自己的分支提交模块代码与报告，向主任务提供SHA；主任务审查、合并、解决兼容和运行闭环。未经用户指定，不创建远程仓库或推送；本地提交不是异地备份。

首轮每个任务至少提供：可运行命令、关键验证结果、已知不足、独立问题MD、环境/容量记录、提交SHA及跨模块交接文件。可以保留真实阻塞，但不能只写计划就声称实现完毕。
