# 下载后真实标注核验方案

日期：2026-09-29。依据本地 `fine_badminton_2026.json`、`bfmd_sources.json`、两份训练来源报告及此前已读作者 README；本轮未联网、未读写 D 盘、未检查实际标注。以下均是 **NOT_RUN 的待执行断言**，服务于 `R-04a`，用途交接另按 `R-04b`；不新增或降低阶段验收门槛。

## 共同前置与输出

1. 先确认下载写者退出、原件大小/哈希合格；Fine 验作者 MD5 并计算 SHA256，BFMD 逐项验精确大小并计算本地 SHA256（无作者哈希，不能宣称作者哈希校验通过）。原件只读，`.part`、HTML、失败文件不参与统计。
2. 保存原 README/LICENSE、归档成员名/CRC/大小、提取路径及文件 SHA 的关系。只运行本项目审计代码；作者辅助脚本只读归档，尤其不执行 YouTube 下载脚本。
3. 输出每文件 schema 摘要、每场计数、分类分布、异常清单与“作者断言/实测/差值/解释证据”。异常记录精确文件、CSV 行号或 JSON pointer；不复制大段标注到 Git。逐文件处理，先估计最大 JSON 的内存峰值，不一次加载全部 1.8 GB。
4. JSON 重复键、NaN/Infinity、解析失败不能被静默覆盖；CSV 保留原编码/分隔符/表头、空值和原行号，不能先用自动类型推断吞掉异常。所有新资产保持 `training_only`、`split=unassigned`，本轮不自动生成 Event。

## Fine-Badminton 2026：10 个 CSV

| 检查 | 输入与执行 | 预期及未解决时的处理 |
|---|---|---|
| 成员与一对一配对 | 使用已校验 ZIP 的**原 member 名**。`annotations/<stem>_dataframe.csv` 只去掉末尾字面后缀 `_dataframe.csv`，与 `videos/<stem>.mp4` 精确匹配；提取路径只作映射，不反向猜原名 | 10 CSV、10 MP4、每个 CSV 唯一对应一个视频，无孤立或重复成员。保留大小写、空格、全角 `！`；不使用模糊匹配/自动改名。路径清理后的大小写碰撞也需报告 |
| schema 和类别映射 | 先读包内 README，再检查每个 CSV 的全部列名、类型、缺失率及原始标签值；识别显式行索引列但不按“第一列”直接删除 | 数字 ID→名称只接受包内作者映射。论文图 6 的顺序是 AP 排序，不能编号。报告无映射值、额外列、各文件 schema 差异；没有映射仍可做原值频数 |
| 行数与类统计 | 每场列出原始数据行、空行、可解析行、含标签行、唯一标签、每类数量、精确重复行及冲突行 | 与 9,817 标注、29 类分别比较。原始计数与去重诊断并列，不为凑数删除重复。公开子集可能未覆盖全词表，区分“声明类别数”和“实际出现类别数” |
| 时间语义 | 记录作者对起止字段、单位、帧基数、端点开闭的说明及证据位置；分清完整文件帧与作者切片内帧 | 目前这些 CSV 语义尚未确认。论文的 `t_s/t_e`、25fps/720p、空档>150帧切片且两端留10帧，不能直接套作公开 CSV 规则。未知则保留原字段并阻塞精确区间转换 |
| 边界和源时间 | 全量检查有限数值、整数性（仅当字段定义为帧）、反向/空区间、排序、重复及重叠；映射经证实后对照实际源帧数和源 PTS | 合法范围取决于0/1基及开/闭端点，不先假设 `end < N` 或 `end <= N`。重叠只列异常候选，不自动判错/合并；可能有两名球员或多标签。禁止默认 `frame/25` 得到原转播时间 |
| 真实抽检和总量 | 每文件固定抽首条、中间条、末条及所有越界候选；在源分辨率/源PTS检查对应画面，报告可见性与边界偏差。分别汇总实际解码帧数与源时长 | 对照 980,703 帧、约10.72h，单列容器报告值和实际解码值。980,703÷25约10.8967h，作者数字不可互相推导填平。agent 抽检不提升为 human 技法真值 |

`videoplayback (1) copy` 可按原 member 正确配对，但姓名/赛事仍未知。每个视频先固定来源组，正式 canonical match_id 只在证据充分后确认；不得因为文件名含 `[Full]` 就宣布没有剪辑、回放或缺段。

## BFMD：115 个活动 JSON 与 1 个备份

先按清单验证 **121 文件/1,825,439,459 B**；115 个活动 JSON 是 1,825,349,511 B，备份 32,751 B，根5文件57,197 B。备份只比较/归档，不进入任何场数、回合或拍数总量。

| 检查与计数来源 | 执行口径 | 避免的错误 |
|---|---|---|
| 比赛全集与模态覆盖 | 根 `match_index.csv`、`Badminton_video_list.csv` 先发现真实列；与12个活动 metadata stem、7个 hits_doubles stem 对照。仅 `court` 精确移除约定 `_court` 后缀；保留原拼写并报告不匹配 | 目标19场=12男单+7男双；九个单打模态各12文件+双打7文件=115，不是115场。未知索引字段不预设列名；caption不漏，backup不加场 |
| 单打回合 | **先验证** metadata 顶层单元素列表及 `games.*.rallies` 实际结构；逐局逐场计列表项，并检查区间。另报 `auto_extracted.num_rallies` 和索引声明；手工 shot_type 中 `Rally` 区间作独立对照 | 主计数不把 metadata、auto_extracted、timeline 和 pose 的同一回合累加；报告彼此差异而不挑较接近1058的数 |
| 双打回合 | 先验证 Label Studio export 实际结构及标注版本。按选定有效版本的 `Rally` ranges 计数；分别报告 result 项数、range 数及多个 annotations/revisions | 不能盲取 `annotations[0]` 当最新；若没有作者版本选择规则，分版本报数，不合并累计。每个 result 可能含多个 ranges |
| 单打拍数 | shot_type 将结构标签与球种标签分开，列原标签→result 数/range 数/有效击球区间数；`hit_inferred.n_hits` 与实际 `hits` 长度单列，并检查 frame/game/rally/player/side 关联 | `hit_inferred` 与手工 shot_type 是同源不同表示，不能相加。结构区间、回放、挑战、间歇不计拍；同帧多条不自动去重 |
| 双打拍数 | `hit`、`bounce`、`net_hit` **逐类分别计数**，结构区间另计；索引若有拍数列，按实际列说明比对 | 不预先把三类之和当“拍数”。明确作者对shot/hit的口径后才计算19场总拍数；否则给各口径候选结果并标记口径未确认，不为得到11301而选择公式 |
| 总量一致性 | 逐场可追溯地汇总已证实口径的 singles+doubles 回合/拍数，对照1,058/11,301；另列索引作者声明的逐场和、缺失和重复 | README overview 的1,687/16,751不是本发布包目标。若不能复现，保留差值、贡献比赛和未解原因，不改门槛 |
| 帧和几何 | 对每模态记录实际帧字段、min/max、缺失、重复及单位；核对跨模态相交范围。已知README全广播0基/30fps，但端点规则仍须读数据说明；court仅主机位，no_court不可用于校准 | BFMD本轮**没有原视频**，因此不能完成真实PTS/总时长/画面边界核验；缺视频不靠作者30fps伪造已验证映射。pose框像素、关键点0–1；bbox/shuttle 0–100，不能统一当像素 |

拍数对账建议输出四列而非一个混合数字：`manual_singles`、`inferred_singles`、`manual_doubles_by_label`、`publisher_index_claim`。只有作者明确对应的口径才比较目标；caption条目数、轨迹点数和pose帧数都不能作额外拍数。

来源分层固定记录：`shot_type`、`hits_doubles` 为**发布者声明的人工标注**，仍是本地未复核 import；`shuttle` 为 TrackNet预测，`hit_inferred` 为推导，`court_perframe` 为自动检测/修复。pose、player_bbox、metadata内各派生字段及caption按作者实际说明补 provenance，不能因为是JSON或Label Studio export就一律标human。项目三细标签继续 unknown。
