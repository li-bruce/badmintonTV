# CPU / NVENC 画质实测

日期：2026-09-29。关联 **R-03a**；分支 `codex/render-presets-acceleration`。本报告完成同一 FFmpeg 8.0.1 下两组真实素材导出的技术画质比较及有限 agent 静帧观察，**不宣布完整 R-03a / S4-03 / S4-04 通过**。人工业务审核、技法/身份真值、连续观看、真实听感与发布许可仍未完成。性能结论见 [本轮报告](ROUND_2026-09-29_RESULTS.md)。

本轮 NVENC 配置相对无损参考的 SSIM / PSNR 更高，文件也明显更大。它与 CPU 配置既非同码率，也非已证明的等质量对照；不能把 CRF 21 与 CQ 21 当作相同质量等级，不能据此宣称某编码器固有更优。

## 参考与帧对齐

[quality_compare.py](../../scripts/render/quality_compare.py) 在任何 reservation / FFmpeg 前，读取两臂原始 `request.json`，经共享 `referenced_assets`、`check_usage`、`verify_source_bytes` 验证全部去重前引用；实际 digest 重新过共享用量门禁。没有用缺少 typed usage 的 source_map 代替 canonical Asset，也没有第二套训练 registry 规则。所用环境为 [render-runtime-compat.json](../../environments/render-runtime-compat.json)：二进制 SHA 已核验，实际 `ffmpeg -version` 完整 stdout 与两臂 QA 一致。

R 从 CPU 每段真实 argv 复用原 `-ss`、输入/输出 `-t`、视频 stream map 与完整 `-vf`，在原 CPU 输出目录 cwd 下读取相同 ASS。只改变视频编码为 FFV1 / yuv420p，使用 NUT 和 `enc_time_base=1/90000`；三个参考段由带显式 duration 的 ffconcat 逻辑拼接，不再写第二份完整参考。ASS 哈希、两臂输入/滤镜、source map、尺寸与 fps 先对齐。

| 检查 | 30fps | 60fps |
|---|---:|---:|
| A / B / R 实际解码帧数 | 512 / 512 / 512 | 1023 / 1023 / 1023 |
| A、B、R stream time_base | 均 1/90000 | 均 1/90000 |
| A/B 逐帧原始 PTS 最大差 | 0 秒 | 0 秒 |
| R/A 逐帧原始 PTS 最大差 | 0 秒 | 0 秒 |

| 每一 SSIM/PSNR 比较帧数 | 512 | 1023 |

PTS 是解码显示顺序中的真实 `frame.pts`，先比较原始 PTS，再以 `settb=1/fps,setpts=N` 配对指标帧；没有先清零掩盖错位。容差为 1/90000 秒。两组输出时长略异是各段独立量化到输出帧数的结果，不拿 30/60fps 的帧序号直接当同一时刻。

首轮脚本记录了 R/A 差值但未将其设为拒绝条件；随后补为硬 assert，并给今后生成的每个 NUT 增加 SHA256。**本次没有重跑成片或覆盖原两份报告**：ROI 旁证重新读取全部原始 probe 帧表，独立 assert A/B/R 帧数和逐帧 PTS，保存原报告 SHA 与六个 NUT SHA；结果均为 0 差。

## 客观指标

R 是编码前相同布局的无损参考；分别计算 CPU/R 与 NVENC/R。`full` 是 1080×1920 全画面；`active_picture` 固定为 `(x=0,y=656,w=1080,h=608)`，适用于本轮方像素、未旋转 16:9 contain 输入。大面积背景和文字会抬高全画面分数，因此两类结果并列。

| fps / 配置 | 全画面 SSIM | 全画面 PSNR dB | 比赛区域 SSIM | 比赛区域 PSNR dB | MP4 bytes | 实测视频流平均 bps |
|---|---:|---:|---:|---:|---:|---:|
| 30 CPU | 0.995890 | 47.545949 | 0.987977 | 43.194564 | 1,009,926 | 461,632 |
| 30 NVENC | 0.997896 | 52.934184 | 0.993735 | 48.324594 | 2,889,238 | 1,342,566 |
| 60 CPU | 0.995250 | 46.543630 | 0.986072 | 42.315934 | 1,086,423 | 494,016 |
| 60 NVENC | 0.998031 | 53.241520 | 0.994158 | 48.648447 | 3,635,540 | 1,690,090 |

此表使用 info 级日志里的 **FFmpeg 最终汇总**。逐帧 stats 用于完整帧数断言、轨迹与近似统计；PSNR 的逐帧 `mse_avg` 会取小数位，先平均这些文本值再重算 dB 只能近似，极低 MSE 还可能被舍入成 0。JSON 同时保存权威汇总和带 `_approx` 的重算值，不能用后者覆盖前者。[FFmpeg PSNR 文档](https://ffmpeg.org/ffmpeg-filters.html#psnr)说明最终平均基于累计 MSE，不是逐帧 dB 的算术平均；[framesync 文档](https://ffmpeg.org/ffmpeg-filters.html#framesync)说明时间配对与末帧重复行为。本次关闭参考末帧延长，并断言日志实际比较数等于全部帧数。

上述分数没有设置“达到某阈值即看清羽球”的业务门槛。小球/脚部局部 ROI 本次用于技术视觉检查，没有另报这些小区域的 SSIM/PSNR。

## 复现与代码验证

使用已有 platform Python（含共享合同依赖），不安装新的库。以 30fps 为例，60fps 替换上表两臂路径：
