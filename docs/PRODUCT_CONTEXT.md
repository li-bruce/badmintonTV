# 产品目标与来源核对

核对日期：2026-09-28。已通过浏览器完整读取用户提供的[共享对话：产品思路](#private-discussion-not-published)，并逐段阅读仓库 `PROJECT_PLAN_SIMPLE.md`。共享对话中的外部研究数字只作为历史背景，实施时应回到一手来源核验。

## 要交付的产品

一个 Python 驱动的本地 Web 工作台，把个人录像和比赛转播变成可搜索的技战术时间线。用户可以管理素材库、手工标注与校正、选择模型、配置LLM、运行分析和看进度、用中文查片段、确认结果、调整剪辑工程并输出完整竖屏集锦。

应用本身和制作出的集锦视频是两种交付。前者要可重复运行，后者要真实、可复核、有完整观看体验。

## 已确认的范围

1. V1 先做文字描述检索，包含手法、步法、手脚组合、多拍先后关系；V2 才把示例视频解析或匹配到库中。
2. 个人录像与赛事转播均可导入，共用业务流程，分开处理镜头/身份变化，并分开报告效果。
3. 搜索返回候选和证据，人工复核后成片。没有完整人工真值时不得声称找到了所有动作。
4. 姿态序列和视频语言模型都试；用同一份比赛划分与查询真值对照 A视频、B骨骼、C融合路线。
5. LLM 负责结构化中文条件、解释和已确认事实的文案；不能把其文本判断当视频真值。
6. 原视频、原始时间码、击球/移动区间、球员映射、模型版本和人工修订需要保留。跨比赛姓名由用户确认，track ID 不是运动员身份。
7. 先以网前展搓/收搓为小案例，再加后退小跳启动。细标签先写可观察定义，视角、球拍/手腕细节不足则 unknown。
8. 本轮明确要求四个额外对话分别推进底座、资料下载、模型训练测试、竖屏集锦。先架构设计再实现测试；模型未完成可保留不可用适配器。
9. 本轮实际资源以本机 RTX 5090 和 WSL 为准；历史提及 H200 不代表现在已有可访问 H200，不依赖它开始工作。
10. 数据/权重在 D:\video，总体不超过700GB；环境隔离、实验失败记录、Git 源码管理是所有模块共同要求。

## 功能边界

首批追求人工索引也能跑通的真实闭环。双打可收集、管理、人工标注和剪辑；双打自动身份/动作识别须单列验证，不继承单打成绩。生成式工具可评估片头包装，比赛动作始终由真实原片组成。
