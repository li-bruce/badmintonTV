# 细动作标注与 A/B/C 评测方案

版本：0.1，2026-09-28。状态：设计完成；尚无本文件对应的真实标注、专家签字或模型成绩。本文服从 `docs/CONTRACTS.md` v1.0 与 `docs/ACCEPTANCE.md`，不扩展公共合同、不承诺细标签已可识别。

## 1. 首轮交付和证据边界

先完成两个小案例：网前展搓/收搓、后退小跳启动。每个案例先证明素材能被人稳定判读，再测试模型；样本不足时交付可复核预标注与缺口清单。粗网前球、清晰的后退移动可独立成为粗粒度基线，不因细标签受阻而停止环境和真实视频推理工作。

公开教学术语、项目机器键、画面观测和真值是四个不同层次。`net_zhan_cuo`、`net_shou_cuo`、`backward_small_hop_start` 是已约定机器键，不能反过来证明技术定义。以下观察清单和窗口为项目建议；展搓/收搓的技术边界、正反手对应和小跳类别边界必须由有羽毛球教学经验的专家确认，并绑定真实锚点。术语尚未统一的样本保留 `unknown`，不由模型或文档作者代替专家定类。

LLM 只能解析中文查询、整理已有观察或生成待核验说明。骨骼点、视频向量、球路分类和模型解释均为预测证据，不是人工真值。ShuttleSet 等来源的 `net shot` 不映射为展搓或收搓。

## 2. 标注对象、时间和最小记录

一个标注对象是一位球员在同一原片、同一回合中的一次击球或一段移动，不是任意裁剪窗口。先关联 `asset_id/match_id/rally_id/player_id`；身份未确认则保留未确认身份或 `null`，不得用镜头内 `track_id` 推断姓名。双打若归属不清，该球员条件为不可判定。

时间使用原片整数毫秒和半开区间 `[start_ms,end_ms)`。播放器代理、慢放、回放的时间须通过原片 PTS 映射回查；不以 `frame_index / fps` 代替 VFR 的实际时间。人工只知道触球范围时，`contact_ms` 保持 `null`，范围记录在模块侧观察记录，不把区间中点假装精确触球时刻。

| 内容 | 最小记录 | 缺失时处理 |
|---|---|---|
| 素材与许可 | asset ID、源文件 hash、比赛/录制会话、来源类别、可用用途 | 未授权素材不纳入可公开成片；真值也保留自身来源 |
| 视角 | 原始机位、球员远/近端、镜像情况、镜头切换、是否回放 | 机位/镜像未知则相关方向特征为 unknown |
| 人员 | 球员 ID、身份依据、持拍手、正/反手观察 | 不从姓名猜惯用手；正反手未知不强行合并 |
| 时间 | 动作起止、触球点或可疑范围、逐阶段锚点、原片 PTS | 缺前后文则截断标志；不能确认完整动作 |
| 可见性 | 手、腕、拍柄、拍头、羽球、双脚、躯干分别记录 | 全局 visibility 不能掩盖关键部位不可见 |
| 判定 | 目标类别 positive/negative/unknown、证据和理由、专家定义版本 | 没有审核的预测不能进入真值快照 |
| 审核 | 两位独立标注、分歧、专家裁决、审核时间、旧版本 | 保留分歧记录，不用多数投票隐藏歧义 |

建议增加的观察字段只写模型模块侧 JSONL sidecar，并由 `event_id` 和 `revision` 关联：`definition_version`、`anchor_set_id`、`racket_hand`、`stroke_side`、`view_context`、`visibility_by_part`、`phase_intervals_ms`、`contact_window_ms`、`observed_features`、`target_judgements`、`reviewers`、`adjudication`、`source_group_id`、`canonical_occurrence_id`。这些字段不是已经获准的 v1.0 公共字段；若平台需要直接编辑，应先提出兼容扩展。

`target_judgements` 是针对某一目标的人工判断，取 `positive/negative/unknown`。公共 Event 的 `labels.hand_technique` 和 `labels.footwork` 仍只用合同允许的目标键或 `unknown`。未知键不承载阴性含义；确认“不是展搓”的证据保留在 sidecar，不借 `review_status=rejected` 充当负类。`review_status=confirmed` 也可表示审核者已经确认该条应保留 unknown，而非确认发生了目标动作。

## 3. 展搓/收搓：先统一术语，再确认可见动作

### 3.1 可观察性准入

初始复核上下文建议为疑似触球前 500 ms 至后 700 ms，并可向两端展开到完整准备与随挥。该窗口是取证起点，不是动作长度真值，也不是必须发生某类球路的硬阈值。保留原速、逐帧、普通慢放；插帧、生成式增强和超分辨率生成的纹理不得用来确认原片缺失的手指、拍面或羽球细节。

需分别检查：

1. 目标球员与这次触球的归属可确定，且触球附近没有切镜头。
2. 球拍与羽球接近、离开的关键阶段有可回查的连续画面；接触瞬间不可见时必须记录不确定范围。
3. 持拍手、拍柄/拍头与躯干的相对轨迹可追踪，足以区别击球动作和击球后的回收动作。
4. 专家认为区分这两个细标签所需的拍面/手腕证据实际可见。低分辨率整场远景只看到手臂，不自动满足本项。
5. 球路可辅助确认这是一拍网前处理；“羽球看似旋转”“落点在网前”“手臂伸出或收回”均不能独立证明展搓/收搓。

只有专家冻结的定义所要求的关键证据全部满足，才能确认细标签。其它非关键部位局部遮挡可设 `visibility=partial` 并说明；关键判别证据缺失即设相应标签 `unknown`，通常为 `visibility=insufficient`。

### 3.2 中立特征表与待专家冻结的判据

先记录中立观察，避免标注员看到术语后寻找符合预期的轨迹。方向参照球员身体与球场，而非屏幕左右；换边、左手、镜像和机位变换必须单独处理。

| 特征 | 如何操作观察 | 禁止推断 |
|---|---|---|
| 持拍方式与击球侧 | 记录左/右手、可辨正/反手及依据帧；无法辨认则 unknown | 不把镜像右手当左手、不由球员姓名推断 |
| 持拍手相对躯干位移 | 标出触球前、接触范围、触球后的手与肩/躯干位置；记录靠近/远离/横向/不可判断 | 不能直接把“靠近”命名为收搓、“远离”命名为展搓 |
| 拍头相对持拍手轨迹 | 在接触局部记录可见弧线、擦切方向及拍头位置变化；标明透视歧义 | 手臂整体位移不等于拍头擦切或手腕动作 |
| 拍面与手腕变化 | 记录实际可见朝向变化及关键帧；拍面边缘不可分辨则 unknown | 不从低分辨率骨骼点重建确定拍面、旋前/旋后或发力机制 |
| 接触与球路 | 保留接触范围、离拍后可见轨迹、是否网前处理 | 球旋转/过网/落点不唯一决定细手法 |
| 随挥与回收 | 将接触局部随挥和下一动作的收拍分开 | 击球后收拍不能补证接触时采用了“收搓” |

**术语冻结流程**：专家对持拍手 × 正反手分别选真实清晰样本；给每个目标至少一组正锚点、另一细标签对照、普通网前处理对照和一个不可判样本，逐段指出必要与非必要证据。若某个分组没有清晰锚点，该分组先不开放细标签。最低锚点组只用于统一定义，不是足以训练或验收的样本量。

| 目标 | 冻结后的操作判定必须包含 | 当前可执行结论 |
|---|---|---|
| `net_zhan_cuo` | 与专家确认展搓锚点一致的接触局部特征组合；明确其与收搓及普通网前处理的区别；注明适用正反手/持拍手/机位 | 名称已固定，技术特征映射待专家确认；现阶段只采集观察，细标签 unknown |
| `net_shou_cuo` | 与专家确认收搓锚点一致的接触局部特征组合；不得仅靠击球后收拍定类；注明适用正反手/持拍手/机位 | 同上，不擅自用身体近/远方向定义技术术语 |
| 两者均无法确定 | 仍可确认粗网前球，但关键细节不可见、定义冲突或不属于已有锚点的适用范围 | `stroke=net_shot` 仅在有证据时记录，`hand_technique=unknown` |

定义版本中必须实际填入锚点 `asset_id + 原片时间 + Event revision`、必要特征、排除条件、专家姓名或受控匿名 ID、确认日期。不能只填“参照教学视频”。技术定义争议尚未解决时不让模型选边，也不把争议样本作为任一类负例。

### 3.3 必收的难负例

难负例是相对于具体目标已确认不成立的清晰样本，不能从未标注窗口自动获得。

| 难负例候选 | 区分所需证据 | 不足时 |
|---|---|---|
| 普通网前放球/推挡与目标细手法相近 | 触球局部手、拍头、拍面证据，专家按冻结定义排除目标 | unknown |
| 展搓与收搓彼此对照 | 相同或可比持拍手/正反手/机位，必要区别均可见 | 不能靠另一粗标签替代 |
| 看似擦切的准备或击球后回收 | 已定位实际接触范围，能区别接触与非接触阶段 | 截断窗口为 unknown |
| 动作相似但属于挑球、勾对角或扑球等其它处理 | 标签体系允许时记录实际粗类别；手法判定仍依专家证据 | 不以球路唯一决定手法 |
| 错球员、同场回放、另一回合中相似动作 | 身份、回合、原始 occurrence 映射 | 用于检索约束负例，不混进动作分类负类 |

## 4. 后退小跳启动：分阶段候选定义

以下是待专家用真实片段验证的**严格项目候选定义**，不是对所有羽毛球小跳或 split step 的通用定义。目标是启动阶段有清晰小跳证据，并紧接同一球员向其后场的移动。方向按球员所在半场到后场的场地坐标解释，不按屏幕向下，也不要求身体始终面向球网。

### 4.1 阶段与必要观察

| 阶段 | 建议边界与可见证据 | 判断限制 |
|---|---|---|
| P0 准备 | 找到启动前可见支撑/准备姿态及位置，作为上下文 | 如果片段一开始已在后退，不能补出起始动作 |
| P1 小跳/卸载候选 | 脚与地面关系、膝髋与躯干变化连续可见；分别记录明确离地与仅疑似卸载 | 髋部抬升不等于双脚离地；2D 点的跳动可能是跟踪误差 |
| P2 落地/推离启动 | 记录各脚落地或承重转换及其先后，不预设两脚同时落地 | 双脚接触关系看不清则不能假填时刻或左右脚顺序 |
| P3 后退移动 | P2 后同一连续动作中，至少一个后续支撑步骤或连续位移显示进入本方后场方向 | 后退距离须超过标注定位不确定性；不能把透视变化当位移 |

严格正例需要 P0→P1→P2→P3 的可见顺序、明确的小跳证据、方向与球员一致、无中间切镜头或另一轮准备重置，并经专家确认该动作应纳入项目目标。**仅有重心变化而看不到离地的情况先记录为卸载候选并标 unknown**；是否纳入无明显腾空的启动、单脚小跳或特定转身启动，由专家另立子类或修订定义，不能事后为提高召回悄悄放宽。

Event 的 `kind=movement`：建议 `start_ms` 为 P1 起始可确认时刻，`end_ms` 为确认 P3 已开始的最早充分区间终点；P0 上下文和 P0–P3 阶段锚点放观察 sidecar/evidence。后退完整路程可另建粗移动事件，起跳击球另建 stroke/shot 事件，避免一个细标签覆盖整段后场过程。需展示更长上下文时，扩展检索候选区间而不改写动作真值边界。

初次审片建议取启动候选前 500 ms 到后 1500 ms，必要时展开。具体持续时间、跳高、“小”的尺度、P2→P3 最大间隔不凭常识写死；用开发集专家锚点冻结可接受范围，保留测量分辨率和机位条件。发生明晰暂停、再次准备或另一独立启动时不连接为同一目标动作。

### 4.2 必收的难负例与未知

| 情况 | 可判定结论 | 必要条件 |
|---|---|---|
| 原地垫步/小跳后仍原地或向前、横向移动 | 对“后退小跳启动”为 negative | 后续位移完整可见，不能在落地时截断 |
| 普通走步、跑步或交叉步后退，启动没有目标小跳 | negative | 完整启动和双脚关系可见；看不到小跳不等于没有小跳 |
| 已在后退过程中的连续跳步 | 若冻结定义只指初次启动，则 negative | 有足够前文证明已经在移动 |
| 为击球起跳或击球后的落地后退 | 若缺独立启动链，则 negative | 触球与脚步时间关系清楚；若含另一次合格启动应分开标 |
| 脚被广告板/另一球员遮挡、远端低分辨率、相机移动 | unknown | 保留 feet_occluded / insufficient_resolution / camera_motion 等原因 |
| 骨骼提示跳动但原片无法确认 | unknown | 模型分数和骨骼插值不能改变原片可见性 |

小跳并非必然代表向后启动；向后位移也不能证明先有小跳。任何一步只有间接证据均要保留该步骤的不确定性。

## 5. Unknown、审核与真值快照

建议模块侧 `unknown_reason_codes`：`definition_unresolved`、`racket_or_wrist_not_visible`、`feet_occluded`、`insufficient_resolution`、`motion_blur`、`contact_between_frames`、`truncated_context`、`camera_cut`、`camera_motion`、`view_ambiguity`、`identity_ambiguous`、`reviewer_disagreement`。公共 Event 的 `unknown_reason` 用简短中文说明具体缺口，可包含多个原因。低模型分数不是画面不可见原因；应另记模型弃权。

1. 从连续真实视频中按预先指定时间或回合选取可观察性小样，不只挑模型高分片段。保留选样方法和排除数量。
2. 两位标注员独立看原片，第一轮不展示模型细标签、分数或另一位答案。先标事实和可见性，再按同一版定义判目标类别。
3. 对全部细标签正例、两类间混淆、所有分歧和不确定原因不一致的样本做专家裁决。初轮小样的细标签负例也全部双人复核；规模扩大后的抽审比例须先登记，并保留可追溯抽样。
4. 专家可确认、修订或保留 unknown；专家也无法从画面区分时不得“必须选一个”。保留原两份判断和裁决理由。
5. 汇总原始一致率、positive/negative/unknown 三态混淆与按类一致率；样本极小或单类时不以一个 kappa 数字宣称可靠。重点列出引起分歧的观察项和机位。
6. 专家定义/锚点冻结后，重新复核受定义改动影响的样本，生成不可变标注快照与 hash。模型预标注、人工修订和审核快照分别保存；不覆盖人工版本。

测试真值不能只审核系统返回的前 K 个片段。需要召回率的任务，必须对选定完整比赛/录制区间穷尽标注该目标的机会与动作，并记录不可判区间；否则只报告“已审核候选准确性”和案例，不计算全片召回。

## 6. 按整场与机位划分，防止泄漏

library 提供原始素材关系；models 在任何训练/阈值/融合选择前冻结 split manifest。分组的基本单元是原始比赛或个人录制会话 `source_group_id`，并包含其全部文件、双机位、转码、相邻片段、集锦、回放与重传。一次实际动作另有 `canonical_occurrence_id`；同动作不同回放只算一个语义命中。

| 评测层 | 划分方法 | 可回答的问题 |
|---|---|---|
| 开发小样 | 若只有一场，全部作为开发/烟测；内部片段切分仅用于调试且不报泛化 | 能否加载、推理、观察和回查 |
| 同域整场留出 | train/validation/test 的原始比赛/会话互斥；相似机位可在不同场出现 | 对新比赛的同域效果 |
| 未见机位/场馆 | 将目标机位或场馆关联的完整比赛组留作独立测试；不让同场其它视角进训练 | 特定新域的迁移效果 |
| 个人 vs 转播 | 两个来源分别统计，并说明是否各自训练/调参 | 两类素材的支持边界 |
| 单打 vs 双打 | 独立测试，尤其列错人和遮挡 | 不能将单打成绩移用于双打 |

同一比赛多机位可用于**仅测试内部**的配对鲁棒性分析，但必须全部属于 test，不能训练一个机位再把另一个机位声称为独立泛化测试。若无法满足新机位与整场互斥，标记该项未测。样本分层不足时给出空格或 `not_measured`，不用总体平均填空。

比例和数量以真实供给为准，不能先随机切片再补分组。建议先获得多个独立比赛组再安排训练/验证/测试；只有一场或每类少于 30 个可判定测试正例时，依据项目验收约定只能报告探索性结果。30 个不是充分泛化保证，还必须报告独立比赛数、分层覆盖和不确定性。

测试集不用于选择窗口、阈值、标签定义、融合权重或模型版本。对测试错误的人工诊断可指导下一轮，但下一轮须使用新的未触碰留出或明确降级为开发结果。记录预训练模型训练来源已知范围；无法排除公开赛事被预训练使用时注明潜在污染。

## 7. A 视频 / B 骨骼 / C 融合实验矩阵

固定同一素材快照、比赛划分、20–30 条真实中文查询及对应经人工核对的 QuerySpec。查询按单拍、脚步、手脚组合、多拍顺序分层；加入同回合对手插拍、同球员不同回合、顺序颠倒、仅差一个步骤等检索难负例。原始中文与手工 QuerySpec 均保留。

先固定人工核对 QuerySpec 比较检索路线，再单独测 LLM 解析并运行端到端实验，避免把解析错误归咎于动作模型。LLM 解析报告 schema 有效率、语义条件错误、身份/范围/顺序错误、unknown 保留、延迟及端点配置；不拿格式正确率代替检索准确率。

| 路线/对照 | 输入与最小实现 | 可验证能力与预期限制（待实测） | 必需输出 |
|---|---|---|---|
| R 人工索引对照 | 人工审核 Event + 固定 QuerySpec + 规则关系查询 | 验证身份/回合/顺序规则及现有标注下可达到的检索参考；受真值缺漏影响，不是绝对理论上限 | 条件命中、缺失、event ID 与原片区间 |
| A 视频 | 现成文字/短视频向量；记录采样 FPS、窗口、步长、裁剪、提示词 | 测候选召回；抽帧可能缺少接触瞬间。只召回相似片段，不自行确认展搓/收搓 | 原始分数、窗口、模型/权重 hash、采样配置 |
| B 骨骼/位置/时序 | 姿态和跟踪→可见性/缺失 mask→场地方向→规则或轻量时序分类器 | 先测移动与小跳链；人体骨骼通常没有充分拍面/羽球信息，不据此确认细手法 | track、关键点置信度与缺失、场地映射质量、阶段候选、弃权原因 |
| C 融合 | A/B 候选并集或重排，身份/回合/时间关系过滤；权重只在 validation 选择 | 检验是否在同审核预算下增加正确候选；缺少 B 的样本应显式降级，不当作负例 | 单路线分数、融合规则/版本、缺失模态、排序依据 |

在机器可运行但缺真值时，A/B/C 允许完成环境、真实视频推理、产物对齐和速度测量；模型卡状态仍为 `experimental`。模型不适配当前 CUDA 算子、未安装或缺权重则分别记真实原因，返回 `blocked` 或相应 manifest 状态，不输出虚构事件。

### 7.1 公平比较和必要消融

- 固定候选时间匹配规则、同一查询、同一去重逻辑和审片界面。A/B/C 既报告各自原生窗口，也报告统一评测映射；不得用真实标签只为某一路线挑窗口。
- 每条查询各评前 K 个候选，`K=min(20,实际候选数)`；同时固定人工审片时间预算。既报告结果质量，也报告返回不足 20 的情况和零返回查询数。
- R、A、B、C 都遵守显式 player/rally 条件；模型身份未确定应进入不确定候选，不强制借用真值身份。可另报使用真值身份的诊断上限，不能与端到端结果混报。
- 必做消融：粗网前标签 vs 细手法；A vs A+B；B 的图像坐标 vs 可验证场地坐标；可见性门控开/关；姿态检测/跟踪误差 vs 人工纠正姿态或身份的诊断结果（若有）。消融按数据能力实施，未做明确列出。
- 仅对已定位的误差做必要轻量训练：时序分类器、小型姿态特征头或现成视频编码器局部微调。训练只用 train 中明确审核标签；unknown 用缺失 mask/忽略标签，不并入 negative，不在同份伪标签上自证准确率。
- 比较 C 的收益时保持审片预算相同。可以报告更多计算成本换来的召回，但不能把更大候选量造成的收益称为免费提升。

## 8. 指标、匹配规则与报告模板

每次实验先登记匹配规则和冻结配置。击球候选需匹配同 asset/原始 occurrence、同球员、同回合，且包含真值接触点或与触球不确定范围相交；另报接触定位误差，禁止用极长窗口掩盖定位失败。初轮建议同时报告接触容差 ±100 ms 和 ±250 ms 的敏感性，不把这两个建议阈值说成已经通过的标准。移动区间报告 temporal IoU 与起止误差，可预登记 IoU≥0.5 作为主匹配门槛并附其它门槛敏感性。阈值最终需在开发阶段结合帧间隔、标注一致性冻结。

多拍查询要求所有已声明步骤及关系都满足，且每步匹配对应真值事件；`before` 允许对手在中间击球，不能简化为数据库邻接。先匹配一次实际动作或序列，再计算命中。同一候选不能重复匹配多个目标来抬高召回；相同动作的重叠窗口/回放在排序评估前按已冻结策略合并，另报原始重复候选比例。

| 指标 | 定义/要求 |
|---|---|
| 数据规模 | 每来源/单打或双打/机位/标签的比赛数、时长、正例、已确认负例、unknown、排除数；测试集逐组列出 |
| 可见性覆盖 | 可判定目标机会数 / 被穷尽审阅的目标机会数；没有穷尽样本时只报抽样可见性与选样偏差 |
| P@K | 判定充分时为 top K 正例数/K；不可判候选 U 个时同时报保守下界 P/K、上界 (P+U)/K、可判覆盖 (K-U)/K，不默默删 unknown |
| 返回覆盖 | 实际 K、零返回查询、达到 20 候选的查询比例；K=0 时 P@K 为不可计算而不是 1 |
| 候选召回 | 命中的唯一可判定真值正例 / 穷尽标注中的可判定正例；明确不含不可判区间，未完整标注则 `not_measured` |
| 细类混淆 | 展搓/收搓/其它已确认动作的混淆、模型弃权率；unknown 真值不计入二分类负例 |
| 边界误差 | 起止与接触绝对误差的中位数、P90、容差内比例；只对已匹配样本统计，同时列漏检和错配 |
| 错人率 | 可判定返回候选中归属错误数/身份可判定候选数；另报身份 unknown 比例 |
| 审核成本 | 每查询审片分钟、每小时原片所需审核分钟、改标签/身份/边界条数、unknown 复核数 |
| 性能 | 解码/预处理/推理/后处理分别耗时和总墙钟时间；每小时原片处理时间、端到端实时因子、峰值 GPU 显存和主存 |
| 稳定性 | 依赖/算子失败、OOM、超时、未处理区间、帧丢失、姿态缺失/ID switch；失败不从平均速度中静默删除 |

分层结果优先于总体平均。P@K 汇总同时给按查询宏平均和候选总量加权结果，并保留逐查询表；召回只对已具备完整真值的集合计算。有限比赛下不确定性可按比赛组重采样；组数太少时直接列逐场值/范围并注明无法稳定估计置信区间，不能把帧或相邻片段当独立样本制造狭窄区间。

速度记录硬件、驱动、WSL、Python、torch/CUDA 编译版本、精度、batch、输入分辨率、采样 FPS、视频总帧数/时长、冷启动与热运行、缓存、CPU/GPU 同时负载。分开报告真实素材速度与合成算子烟测。小样外推 100 小时只可称估算，列假设，不称已处理 100 小时。

每条实验记录至少含：experiment/run ID、日期、代码 SHA、依赖锁和权重 hash、配置、数据/真值/split hash、查询版本、匹配规则、命令、资源/容量、成功与失败日志、逐层结果、典型错误原片引用、限制、下一步。大特征和媒体只存受控 models 目录；Git 仅保留小型清单与报告。
