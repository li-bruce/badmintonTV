# badmintonTV 框架与使用手册

这套系统的目标是把真实比赛视频变成可标注、可检索、可复核的技战术资料，再把有制作权限的片段做成竖屏集锦。本轮正在增加独立的训练工作区，让你逐步构建自己的动作与态势数据集；以下步骤会随集成验收更新可用状态。

**阅读提示：本手册解释产品结构和操作原则。** 本轮实际交付与未完成项以[验收记录](ROUND_VALIDATION_2026-10-02.md)为准；已有模型能输出特征，不代表全部手法、步法和战术已经识别准确。

## 1. 两条业务线，共用一个底座

| 训练数据线 | 制作素材线 |
|---|---|
| 训练视频 → 人工标注 → 审核与分组 → 数据集快照 → 数据检查 → 有条件地训练/评测 | 有使用权的素材 → 分析/人工标注 → 检索候选 → 确认 → 时间线 → 成片 |
| 目标是建立可信监督数据 | 目标是找片段并制作视频 |
| 可以使用本项目已登记的研究训练包；保持training_only | 只接受制作用途允许的素材；原片权利仍需核实 |
| 导出的首先是标注和原片引用，不必复制视频 | 编码时才生成最终MP4 |

训练出的合格模型可以应用到制作素材。训练原片、代理或衍生片段不能因此进入制作库，研究预览也不能绕过这条约束。

## 2. 第一次使用：先做一个完整的小回合

1. 打开“训练标注”，建立或选择一个训练项目，选择已有目录中的视频。视频较长时先选一小段完整回合。
2. 绑定比赛内的球员与队伍。可先用“A/B”或“A/B/C/D”，不必提前知道姓名；换边后仍是同一人。
3. 记录回合开始和结束。开头可用发球触球；结束应根据死球，不能用最后一次触球自动代替。
4. 在每次触球位置放mark，并选择击球者。看不清时记录不确定范围或unknown，不强猜某一帧。
5. 给动作或移动过程画区间，分别选择球种、手法、步法、球路和状态标签。一个片段可以有多个标签。
6. 保存并重新打开确认内容。明确确认过的人工标注才用于默认训练视图；未确认和机器建议继续留在审核区。
7. 按比赛或录制会话分配训练/验证/测试组，导出快照并查看数据检查结果。缺少独立比赛或审核标签时，先得到缺口清单，不会凭空开始可靠训练。

只需先完成一个真实回合，就能验证你的标签定义和操作方式是否合适。随后扩大到不同球员、近远端、机位和单/双打，避免整份数据只代表一种画面。

## 3. 触球mark、动作区间和回合有什么区别

| 对象 | 含义 | 例子 |
|---|---|---|
| 触球mark | 时间锚点，可带不确定范围 | A在12.48秒附近击球 |
| 球路区间 | 本次触球到下一次触球或死球 | A触球后球飞向B，直到B接触 |
| 手法区间 | 准备、触球、随挥的一段过程 | 不能只留触球那一帧判断切削 |
| 步法区间 | 启动、移动、到位、支撑、落地、回位 | 需要观察连续脚步和对手触球时机 |
| 回合 | 发球到死球的连续对打 | 含双方多次触球，或双打四人参与 |
| 战术模式区间 | 有证据关联的多拍过程 | 连续压后场后改打网前 |

mark修改后，应重新检查由它派生的区间。不同用途可得到不同范围，原片仍保留一份。自动补的边界要标为候选；没有下一次触球或死球证据时，不能把猜测写成精确结束。

## 4. 要标哪些内容

| 层次 | 记录什么 | 看不清时 |
|---|---|---|
| 击球 | 球种、正反手、绕头、方向、可见的手拍细节 | 可以只确认粗类，细手法unknown |
| 步法 | 启动、并步/交叉/跑步/弓步、到位、起跳落地、回位 | 仅有位移时不猜具体步序 |
| 球 | 可见位置、来去球、轨迹与时序 | 缺失与插值分开；不伪造旋转和三维高度 |
| 本人和对手 | 位置、移动方向、击球/接球角色、可见姿态 | 每个字段独立unknown |
| 双打搭档 | 队伍、阵形、接球责任、补位与角色变化 | 人物遮挡或关联不稳时保留待审 |
| 多拍模式 | 前后调动、持续压制、下压跟进、攻防转换、轮转等 | 需要完整相关事件，不凭单个姿势定战术 |
| 意图/评价 | 对模式的解释、可能目的和其它选择 | 是假设或教练评价，不能回写成观察事实 |

展搓、收搓、后退小跳只是示例。完整家族、定义和论文路线见[能力方案](END_TO_END_CAPABILITY_PLAN.md)。目录会迭代：稳定标签ID保持可追溯，旧快照保留当时的词表版本。

## 5. 怎样理解保存、审核和unknown

“保存”表示记录已持久化；“确认”表示对当前修订作出了明确审核。改动已确认内容后，需要检查新修订，不能沿用旧确认。两人同时编辑同一版本会产生冲突，系统不应静默覆盖。

| 状态或来源 | 如何用于数据集 |
|---|---|
| 人工明确确认、证据充分 | 可以进入相应标签的训练视图 |
| 模型预标、agent操作测试、待审核 | 可供继续审核，不作为专家人工真值 |
| unknown / 看不清 / 有歧义 | 记录缺失原因，不当作“这个动作没有发生” |
| 未标注 | 只是没有标签，不能自动当负例 |
| 明确阴性 | 人工确认该标签不成立，才用于对应负例 |
| 不适用 | 此字段在当前任务无意义，例如单打没有搭档 |

你不需要一次把所有标签填满。先标自己能够判断的层次，将不确定项交给后续复核，比强制选一个类别更有价值。

## 6. 数据集快照是怎样生成的

快照像一次“封存版本”：包含当时的视频身份、标签目录、标注内容与修订、比赛分组、划分策略和质量摘要。以后修改在线标注，不会改变旧快照，因此训练结果能追溯到具体输入。

按整场比赛或录制会话划分，再切成训练窗口。同场的相邻回合、回放、转码、重复下载和派生片段归同组，不能随机分到训练与测试两侧。文件名不同不等于来源独立。

数据检查会回答：有哪些可用标签；哪些记录未审核；每类有多少独立来源；人物/回合引用和时间是否完整；划分是否有泄漏；哪些类暂时不能训练或评价。**检查通过是数据准备通过，不是模型精度通过。**

## 7. 模型怎样理解动作和态势

整体采用分层处理，各部分可以替换：

1. 识别有效比赛画面、回放和镜头变化。
2. 找到球场、球员、骨骼、羽球；需要时增加球拍或脚部细节。
3. 找击球时刻、击球者与动作区间。
4. 同时判断手法、步法和球路，并构建本人、对手、搭档的状态。
5. 根据连续多拍识别有明确定义的技战术模式，再生成带证据的解释。
6. 将候选交给人审核、检索或数据集构建。

同样的后场球可能是主动压制，也可能是被动过渡，要看双方位置和来球。态势能帮助判断，但不能补出画面没拍清的握拍或脚步。离线复盘可以使用声明窗口内的后续画面；实时判断只能使用当时已经出现的信息。

目前优先复用已跑通的姿态、TrackNet和视频向量组件，训练小型击球/动作/步法分类头及态势融合模块。没有合格人工标签时，先做工具和真实基线；不从零训练大模型。

## 8. 四个模块怎样协作

| 模块 | 用通俗的话说 | 交付给下一环节 |
|---|---|---|
| 01 平台 | 把全部流程放在一个可操作页面里 | 注册视频、标注版本、任务、快照、候选与时间线 |
| 02 资料库 | 确认视频从哪来、是什么、能怎么用 | 可信目录、来源/许可、hash、PTS和比赛分组信息 |
| 03 模型 | 把视频变成候选事实，并检查能否训练 | 特征、候选标签、质量/训练准备报告、模型版本与真实实验 |
| 04 渲染 | 根据标记生成范围，并把合法素材合成视频 | 可追溯的窗口/时间线、MP4、源片映射与QA |

平台不直接装训练框架，模型不直接修改业务数据库。各模块通过明确的JSON合同交接；界面不应因为模型暂时不可用而无法人工标注。

## 9. 文件、环境和资源放在哪里

| 位置 | 放什么 |
|---|---|
| 项目Git仓库 | 源码、配置模板、说明、用例与报告；不放视频/权重/凭据 |
| D:/video/data | 原视频、公开训练资料、来源与交接清单，由资料模块管理 |
| D:/video/platform | 数据库、标注快照、预览和平台产物 |
| D:/video/models | 权重、特征、训练checkpoint及模型实验产物 |
| D:/video/render | 编码中间文件、成片和质量报告 |
| D:/video/runtime | 各模块隔离环境和工具；WSL必要环境也计入对应预算 |

总上限700十进制GB，包含缓存、临时文件、解压双份和环境。原片只读复用，各模块按固定配额预检；不会因换了目录就重新拥有700GB预算。

平台服务绑定本机地址。模型训练只在WSL隔离环境，5090由统一排期管理；CPU标注与文档阅读无需GPU。未安装模型、资源不足和缺少标签都应显示真实原因。

## 10. 如何启动与找到网页

主工作台约定地址为`http://127.0.0.1:18080/`，训练页为`/training`，本手册为`/guide/`。网页需要服务正在运行；已有数据不会因为关闭浏览器消失。当前可用入口和最后实测时间见[本轮验收](ROUND_VALIDATION_2026-10-02.md)。

常规启动、worker和既有适配器见[启动说明](QUICKSTART.md)。修改数据库或重启前先确认当前任务状态，不结束无关服务/GPU进程。若启动器提示端口已占用，先核对已有服务，不重复启动覆盖。

本手册由Markdown静态生成，可以直接打开HTML离线阅读；离线文件中的“打开工作台”需要本地服务。页面提供章节目录、当前页搜索和打印，无需CDN或联网登录。

## 11. 看到错误时怎样处理

| 现象 | 应查看什么 | 下一步 |
|---|---|---|
| 视频不能播放 | 是否已登记、hash是否变化、编码/预览状态 | 保留原片，重新核验或生成受控兼容预览 |
| 触球位置不够精确 | 浏览器时间还是源PTS、是否代理降帧 | 用源帧核查；必要时记录时间范围 |
| 保存冲突 | 页面版本是否早于服务端 | 重载并比较，不强制覆盖另一份修订 |
| 不能导出正式训练集 | 审核来源、unknown、比赛分组和split报告 | 补相应条件；可保存草稿用于继续标注 |
| 模型不可用 | not_installed、依赖、GPU窗口或缺真值 | 按具体原因处理，继续人工流程 |
| 训练片段不能生成集锦 | 是否training_only或继承训练来源 | 使用有制作权限的独立素材，不能改用途字段绕过 |

失败也是记录的一部分：保存实际输入、代码与模型版本、错误、未达标原因和下一步。没有实际验证就标NOT_RUN；明确缺前提用BLOCKED。

## 12. 怎么判断阶段真的完成

每阶段采用“给定输入 → 执行 → 断言”的用例。PASS代表指定证据满足全部要求；FAIL代表实际不符合；BLOCKED代表缺前提；NOT_RUN代表尚未运行。阶段全部必需项PASS才算达标。

本轮先交付可用工具，并验证真实视频打开、标记、保存、快照、模型侧检查、用途隔离和服务重启。专家标签、陌生比赛精度、双打泛化、整链实时分别验收，不能被软件测试数量或一段成功推理替代。
